# Tsumiki

**Tsumiki** はショートリード (シングルエンド / ペアエンド) 向けの de novo ゲノムアセンブラです。
信頼できる k-mer から de Bruijn グラフを組み、複数の k とペアの情報を使って contig・scaffold を作ります。

> [!CAUTION]
> Tsumiki は開発中の実験的なソフトウェアです。検証は [GAGE-B](#ベンチマーク) の細菌ショートリード 12 データセット (HiSeq・MiSeq) に限られており、
> それ以外の条件 (真核生物、メタゲノム、リード長 250 bp を超えるものなど) での挙動は分かっていません。
> 結果を解析に使う場合は、QUAST などによる参照ゲノムとの比較で正しさを確認してください。

## 動作環境

- Windows (x64)
- Linux (x64)：Ubuntu 24.04 で動作を確認しています。Release で配っている実行ファイルは glibc 2.34 以上が必要です (Ubuntu 22.04・Debian 12・RHEL 9 以降)
- ビルドには [.NET 10 SDK](https://dotnet.microsoft.com/download) が必要です
- Linux (arm64) / macOS は現時点で未検証です

## インストール

ソースからビルドします。

```bash
git clone https://github.com/viral8code/Tsumiki.git
```

```bash
cd Tsumiki
```

単体の実行ファイル (Native AOT) を作る場合は、Visual Studio の「C++ によるデスクトップ開発」ワークロードが必要です。

```bash
dotnet publish Tsumiki.csproj -c Release -o publish
```

C++ ツールチェーンがない場合は、Native AOT を無効にしてビルドします。この場合は `Tsumiki.exe` の実行に .NET 10 ランタイムが必要です。

```bash
dotnet publish Tsumiki.csproj -c Release -p:PublishAot=false -o publish
```

ヘルプが表示されればインストール完了です。

```bash
publish/Tsumiki.exe -h
```

## クイックスタート

ペアエンドリード:

```bash
Tsumiki.exe -1 reads_R1.fastq.gz -2 reads_R2.fastq.gz -t out
```

シングルエンドリード:

```bash
Tsumiki.exe -1 reads.fastq.gz -t out
```

スレッド数・メモリ・k を指定する例:

```bash
Tsumiki.exe -1 reads_R1.fastq.gz -2 reads_R2.fastq.gz -k 31,51,71 -th 16 -mem 4G -t out
```

完了すると `out/assembly.fasta` が最終的なアセンブリです。

既定では前処理・エラー訂正・multi-k・局所ギャップ充填・ポリッシュなど主要な処理がすべて有効になっているため、通常は入力と出力先を指定するだけで十分です。

### HiSeq と MiSeq を混ぜた場合

同じ株の HiSeq と MiSeq が揃う 3 種では、両方のリードを 1 回の実行に渡した結果も載せます (条件は上と同じ)。

| データセット | 深度 | 参照の水準 | contig 数 | 総延長 | N50 | NA50 | 誤結合 | 局所誤結合 | ゲノム被覆率 |
|---|---:|---|---:|---:|---:|---:|---:|---:|---:|
| M. abscessus 6G-0125-R | 205x | Contig (5) | 47 | 5,136,225 | 286,316 | 286,316 | 1 | 0 | 99.82% |
| R. sphaeroides 2.4.1 | 325x | **Complete** (7) | 114 | 4,581,406 | 182,920 | 182,920 | 2 | 1 | 99.17% |
| V. cholerae CP1032(5) | 195x | Contig (17) | 77 | 3,930,246 | 246,185 | 246,185 | 5 | 1 | 98.69% |

3 種とも NA50 がどちらか単独のときより大きくなりました (M. abscessus と V. cholerae は単独の 1.5 倍以上)。誤結合の数は、HiSeq 単独と MiSeq 単独の間に収まっています。

### 数字の読み方

**参照の水準**は、比較に使った参照ゲノムがどこまで組み上がっているかです。`Complete` は完成ゲノム、`Scaffold` は N でギャップを埋めた超コンティグ、`Contig` は隣接情報を持たない断片で、括弧内は参照の配列本数です。

**参照が断片的なほど誤結合は多く数えられます。** 参照側で切れている場所は、実際には連続していても「参照と食い違う結合」と判定されるためです。12 データで参照の配列本数と誤結合数の相関は **+0.97** でした。X. axonopodis の誤結合 58 件は参照が 151 本に分かれていることをほぼそのまま反映しており、同じデータのゲノム被覆率は 99.84% と 12 データ中で最も高い水準です。誤結合の数はデータセット間で直接比べられません。

完成ゲノムを参照に使えるのは R. sphaeroides と B. cereus ATCC 10987 (MiSeq) で、誤結合はそれぞれ 1 (HiSeq)・2 (MiSeq)・4 件です。

**誤結合には、読んだ株と参照の構造の違いも含まれます。** R. sphaeroides では HiSeq・MiSeq・混合のすべてで、参照の 36.5 kb 付近と 64.5 kb 付近をつなぐ同じ継ぎ目が 1 件ずつ数えられています。この継ぎ目をまたぐ 40 塩基は生のリード 176 本 (HiSeq) にそのまま含まれている一方、参照には似た並びもありません。組み立ての誤りではなく、シーケンスされた株が参照と違う構造を持っているとみられます。

**深度は精度に効いていません。** 89x から 332x まで 3.7 倍の幅がありますが、深度と NA50 の相関は **−0.16** でした。

### 再現方法

```bash
Tsumiki.exe -1 <reads_1.fastq> -2 <reads_2.fastq> -mg -th 16 -mem 8G -t <出力先>
```

HiSeq と MiSeq を混ぜる場合は、`-1`・`-2` にそれぞれカンマ区切りで並べます。

```bash
Tsumiki.exe -1 <hiseq_1.fastq>,<miseq_1.fastq> -2 <hiseq_2.fastq>,<miseq_2.fastq> -mg -th 16 -mem 8G -t <出力先>
```

```bash
quast.py -o <出力先> -r <参照.fna> --min-contig 500 <出力先>/assembly.fasta
```

## 入力

- FASTQ 形式 (`.gz` 圧縮にも対応)
- ペアエンドの場合は R1 と R2 を別ファイルで渡し、両ファイルのリード順を揃えてください (インターリーブ形式には未対応)
- クオリティのオフセット (Phred+33 / +64) は自動判定します
- `N` などの曖昧塩基を含む領域は、既定では k-mer カウントから除外されます

## オプション

全オプションは `Tsumiki.exe -h` で確認できます。

### 基本

| オプション | 説明 | 既定値 |
|---|---|---|
| `-1 <path>` | R1 (シングルエンドの場合はそのリード) の FASTQ。カンマ区切りで複数ライブラリを渡せます | **必須** |
| `-2 <path>` | R2 の FASTQ。`-1` と同じ順でカンマ区切り | なし |
| `-s <path>` | シングルエンドの FASTQ。カンマ区切りで複数指定でき、`-1`/`-2` のライブラリに加わります | なし |
| `-t <path>` | 出力ディレクトリ | `temp` |
| `-th <int>` | スレッド数 | 論理プロセッサ数 |
| `-mem <size>` | k-mer カウントに使うメモリの上限 (例: `512M`, `4G`) | 使えるメモリの 1/8 (`768M`〜`4G` の範囲) |
| `-lang <ja\|en\|zh>` | メッセージの言語 | `ja` |
| `-log <quiet\|normal\|verbose>` | コンソール出力の詳細度 | `normal` |
| `-v` | バージョンを表示 | |
| `-h` | ヘルプを表示 | |

### k-mer・クオリティ

| オプション | 説明 | 既定値 |
|---|---|---|
| `-k <int[,int...]>` | k-mer 長。カンマ区切りで複数指定すると各 k で組んで最良の結果を選びます | リード長から自動選択 |
| `-kc <int>` | 信頼する k-mer の最小出現回数 | k-mer スペクトルから自動選択 |
| `-q <int>` | 信頼する塩基クオリティの下限 | `1` |
| `-qt <int>` | 前処理で、ペアエンドリードの 3' 末端から品質がこの値を下回る区間を切る (BWA の `-q` と同じ方式)。`0` で切らない。シングルエンド (`-s`) には効かない | `0` |
| `-p <33\|64>` | Phred オフセット | 自動判定 |
| `-ab` | 曖昧塩基 (IUPAC コード) を展開して利用する | 無効 |

### ペアエンド・scaffolding

| オプション | 説明 | 既定値 |
|---|---|---|
| `-mode <conservative\|normal\|bold>` | contig 同士をつなぐ積極性のプリセット。`conservative` は誤結合を減らし、`bold` はより長くつなぎます | `normal` |
| `-i <int>` | インサートサイズ (bp) | マッピング結果から自動推定 |
| `-pu <decimal>` | 接続を採用するのに必要な優勢比率 (`-mode` より後に書くと上書き) | `0.8` |
| `-pc <int>` | 短い反復を解決するのに必要なペア数 (`-mode` より後に書くと上書き) | `10` |

`-mode` の各プリセットの値は次のとおりです。

| `-mode` | `-pu` | `-pc` |
|---|---|---|
| `conservative` | 0.9 | 15 |
| `normal` | 0.8 | 10 |
| `bold` | 0.65 | 5 |

### 処理の有効・無効

既定では以下の処理がすべて有効です。個別に無効にするには、`-n` で始まるオプションを指定します。

| オプション | 無効にする処理 |
|---|---|
| `-npp` | 前処理 (アダプタ読み抜けの除去、ペアの重なりによる訂正) |
| `-nec` | k-mer スペクトルによるエラー訂正 |
| `-nmk` | multi-k アセンブリ (1 つの k で組み立てる) |
| `-nc` | k 間の配列引き継ぎ |
| `-nsr` | ペアをつないだ合成リードの引き継ぎ |
| `-nrv` | 反復を複製する前のリードでの裏付け (r-mer 検証) |
| `-nla` | 未閉鎖ギャップの局所アセンブリ |
| `-nmy` | 信頼 k-mer に挟まれた低頻度 k-mer の救済 |
| `-nt` | 低カバレッジなグラフ末端のトリミング |
| `-npo` | ポリッシュ (置換エラーの修正) |
| `-ncc` | 環状配列の接合部の検証 |
| `-ngfa` | GFA1 形式のグラフ出力 |

```bash
Tsumiki.exe -npo -ngfa -1 reads_R1.fastq.gz -2 reads_R2.fastq.gz -t out
```

既定で無効な処理と、その他の設定は次のとおりです。

| オプション | 説明 | 既定値 |
|---|---|---|
| `-mg` | 他の k の配列で未連結箇所を補う (誤アセンブリが増える可能性あり) | 無効 |
| `-cnb <spectrum\|weighted>` | コピー数推定の基準深度の求め方 | `weighted` |

### 出力ディレクトリ・中間データ

| オプション | 説明 | 既定値 |
|---|---|---|
| `-rs` | 既存の出力ディレクトリから再開する (前処理・訂正済みリードと、終わっている k のアセンブリを再利用) | 無効 |
| `-rt` | 正常終了後に中間ファイルを削除する (最終結果とログは残ります) | 無効 |
| `-inmem` | 中間のリードと k-mer 計数の途中結果をディスクではなくメモリに置く。ディスクへの読み書きが大きく減る代わりに、メモリ使用量が増える | 無効 |

### 同時に指定できない組み合わせ

次の組み合わせを指定すると、実行を始めずに理由を表示して終了します。

| 組み合わせ | 理由 |
|---|---|
| `-inmem` と `-mem` | `-inmem` は k-mer 計数の途中結果をメモリに置くため、ディスクへ逃がす前提の `-mem` と食い違う |
| `-inmem` と `-rs` | `-inmem` では再開の元になる中間ファイルがディスクに残らない |
| `-nmk` と複数の値を渡した `-k` | カンマ区切りの `-k` は「各値を試して最良を選ぶ」指定 |
| `-i` と 2 つ以上のペアエンドライブラリ | 1 つの値がすべてのライブラリに当てられ、インサートの違うライブラリの前提が崩れる |

## 出力

`-t` で指定したディレクトリに出力されます。

| ファイル | 内容 |
|---|---|
| `assembly.fasta` | **最終的なアセンブリ結果。通常はこれを使ってください** |
| `scaffolds.fasta` | scaffold 配列 (ポリッシュ前) |
| `contigs.fasta` | contig 配列 (scaffolding 前) |
| `unitigs.fasta` | unitig 配列 |
| `assembly.agp` | `assembly.fasta` の構成 (AGP v2.1)。推定した長さのギャップは種類 `N`、リードのペアで繋がるが重なりを確かめられなかった箇所は `N` を 100 個並べて種類 `U` (長さ不明) と記します |
| `assembly.gfa` | アセンブリグラフ (GFA1)。[Bandage](https://rrwick.github.io/Bandage/) などで可視化できます |
| `assembly.report.json` | 配列統計と各種検証結果 |
| `assembly.ambiguous.tsv` | 曖昧さが残った箇所の一覧 |
| `assembly.unsupported.tsv` | リードによる裏付けが得られなかった区間の一覧 |
| `assembly.junctions.tsv` | 継ぎ目ごとの、繋ぐ相手を誤っている確率 (下の「継ぎ目の誤り確率」) |
| `assembly.safe.fasta` | `assembly.fasta` を、誤りの確率が 0.5 以上の継ぎ目で切ったもの |
| `assembly.provenance.json` | 実行時の設定・入力ファイルのハッシュなどの記録 |
| `Tsumiki.log` | 実行ログ (`-log` の設定に関係なく全ログを保存) |

このほか、k ごとの途中結果 (`k31/` など) や検証用のファイルが作られます。不要であれば `-rt` で自動削除できます。

## 継ぎ目の誤り確率

ペアエンドのリードがあれば、最後に元のリードを `assembly.fasta` へペアのまま当て直し、反復を挟んで両側の固有配列を繋いだ箇所と N のギャップ (継ぎ目) ごとに、繋ぐ相手を誤っている確率を `assembly.junctions.tsv` に書き出します。
位置は 0 始まりで、`end` は含みません。確率の列は `misjoin_probability` です。

確率は、反復の長さ・コピー数・継ぎ目を跨ぐリードとペアの数とその期待値・相方が正しく組めないリードの数・両側の深さから求めます。
ペアで跨げる継ぎ目 (`span`)、ペアで跨げない継ぎ目 (`nospan`、反復がインサートより長いなど)、N のギャップ (`gap`) の 3 つに分けて、完全長の参照がある実データ (Tsumiki と他のアセンブラの計 66 アセンブリ) で水準を合わせています。
確率の合計がそのアセンブリの誤りの期待件数の目安になり、ログにも出ます。確率の高い継ぎ目から確かめるか、下流の解析で気になる箇所がその近くに無いかを見るのに使ってください。

誤りの確率が 0.5 以上 (誤りの方が起きやすい) の継ぎ目で切った配列を `assembly.safe.fasta` に書き出します。反復の区間は両側の片に残し、N のギャップで切るときは N を落とします。
繋がりの長さより誤結合の少なさを優先したいときに使ってください。

## 途中から再実行する

出力先にすでにディレクトリがある場合、結果が混ざるのを防ぐため実行を中止します。
途中で止まった実行を再開する場合は、同じ入力とオプションに `-rs` を付けて実行します。前処理・エラー訂正の結果と、最後まで終わっている k のアセンブリを再利用し、止まった k から続けます。

```bash
Tsumiki.exe -1 reads_R1.fastq.gz -2 reads_R2.fastq.gz -t out -rs
```

入力ファイル・設定・Tsumiki の版が変わっている場合、該当する処理は自動的にやり直されます。
k のアセンブリは前から順に再利用し、1 つでもやり直した k があれば、それより後の k もやり直します (後の k は前の k の結果を引き継いでいるため)。

## ヒント

- **メモリ**: `-mem` は k-mer カウントのみの上限です。グラフ構築などで別途メモリを使うため、実際の使用量はこれより大きくなります。
- **実行時間**: multi-k は複数の k でアセンブリを繰り返すため時間がかかります。急ぐ場合は `-k 55` のように k を 1 つだけ指定してください。
- **k の選び方**: `-k` を指定する場合は、リード長より小さい値にしてください。
- **正しさの確認**: N50 が大きいことや、配列が環状と判定されたことだけでは、正しく組めた保証にはなりません。
