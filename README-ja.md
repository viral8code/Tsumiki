# Tsumiki

**Tsumiki** はショートリード (シングルエンド / ペアエンド) 向けの de novo ゲノムアセンブラです。
信頼できる k-mer から de Bruijn グラフを組み、複数の k とペアの情報を使って contig・scaffold を作ります。

> [!CAUTION]
> Tsumiki は開発中の実験的なソフトウェアです。実データでの精度や必要な計算資源は、まだ十分に検証されていません。
> 結果を解析に使う場合は、QUAST などによる参照ゲノムとの比較で正しさを確認してください。

## 動作環境

- Windows (x64)
- ビルドには [.NET 10 SDK](https://dotnet.microsoft.com/download) が必要です
- Linux / macOS は現時点で未検証です

## インストール

ソースからビルドします。

```bash
git clone https://github.com/viral8code/Tsumiki.git
```

```bash
cd Tsumiki
```

単体の実行ファイル (Native AOT) を作る場合は、Visual Studio の「C++ によるデスクトップ開発」ワークロードが必要です。

```bash
dotnet publish Tsumiki.csproj -c Release -o publish
```

C++ ツールチェーンがない場合は、Native AOT を無効にしてビルドします。この場合は `Tsumiki.exe` の実行に .NET 10 ランタイムが必要です。

```bash
dotnet publish Tsumiki.csproj -c Release -p:PublishAot=false -o publish
```

ヘルプが表示されればインストール完了です。

```bash
publish/Tsumiki.exe -h
```

## クイックスタート

ペアエンドリード:

```bash
Tsumiki.exe -1 reads_R1.fastq.gz -2 reads_R2.fastq.gz -t out
```

シングルエンドリード:

```bash
Tsumiki.exe -1 reads.fastq.gz -t out
```

スレッド数・メモリ・k を指定する例:

```bash
Tsumiki.exe -1 reads_R1.fastq.gz -2 reads_R2.fastq.gz -k 31,51,71 -th 16 -mem 4G -t out
```

完了すると `out/assembly.fasta` が最終的なアセンブリです。

既定では前処理・エラー訂正・multi-k・局所ギャップ充填・ポリッシュなど主要な処理がすべて有効になっているため、通常は入力と出力先を指定するだけで十分です。

## 入力

- FASTQ 形式 (`.gz` 圧縮にも対応)
- ペアエンドの場合は R1 と R2 を別ファイルで渡し、両ファイルのリード順を揃えてください (インターリーブ形式には未対応)
- クオリティのオフセット (Phred+33 / +64) は自動判定します
- `N` などの曖昧塩基を含む領域は、既定では k-mer カウントから除外されます

## オプション

全オプションは `Tsumiki.exe -h` で確認できます。

### 基本

| オプション | 説明 | 既定値 |
|---|---|---|
| `-1 <path>` | R1 (シングルエンドの場合はそのリード) の FASTQ | **必須** |
| `-2 <path>` | R2 の FASTQ | なし |
| `-t <path>` | 出力ディレクトリ | `temp` |
| `-th <int>` | スレッド数 | 論理プロセッサ数 |
| `-mem <size>` | k-mer カウントに使うメモリの上限 (例: `512M`, `4G`) | `768M` |
| `-lang <ja\|en\|zh>` | メッセージの言語 | `ja` |
| `-log <quiet\|normal\|verbose>` | コンソール出力の詳細度 | `normal` |
| `-v` | バージョンを表示 | |
| `-h` | ヘルプを表示 | |

### k-mer・クオリティ

| オプション | 説明 | 既定値 |
|---|---|---|
| `-k <int[,int...]>` | k-mer 長。カンマ区切りで複数指定すると各 k で組んで最良の結果を選びます | リード長から自動選択 |
| `-kc <int>` | 信頼する k-mer の最小出現回数 | k-mer スペクトルから自動選択 |
| `-q <int>` | 信頼する塩基クオリティの下限 | `1` |
| `-p <33\|64>` | Phred オフセット | 自動判定 |
| `-ab` | 曖昧塩基 (IUPAC コード) を展開して利用する | 無効 |

### ペアエンド・scaffolding

| オプション | 説明 | 既定値 |
|---|---|---|
| `-mode <conservative\|normal\|bold>` | contig 同士をつなぐ積極性のプリセット。`conservative` は誤結合を減らし、`bold` はより長くつなぎます | `normal` |
| `-i <int>` | インサートサイズ (bp) | マッピング結果から自動推定 |
| `-pu <decimal>` | 接続を採用するのに必要な優勢比率 (`-mode` より後に書くと上書き) | `0.8` |
| `-pc <int>` | 短い反復を解決するのに必要なペア数 (`-mode` より後に書くと上書き) | `10` |

`-mode` の各プリセットの値は次のとおりです。

| `-mode` | `-pu` | `-pc` |
|---|---|---|
| `conservative` | 0.9 | 15 |
| `normal` | 0.8 | 10 |
| `bold` | 0.65 | 5 |

### 処理の有効・無効

既定 (`-profile standard`) では、以下の処理がすべて有効です。

- 前処理 (アダプタ読み抜けの除去、ペアの重なりによる訂正)
- k-mer スペクトルによるエラー訂正
- multi-k アセンブリと k 間の配列引き継ぎ
- 反復部分の r-mer 検証
- 未閉鎖ギャップの局所アセンブリ
- 低頻度 k-mer の救済
- ポリッシュ (置換エラーの修正)
- 環状配列の接合部の検証
- GFA 出力

一部だけを有効にしたい場合は、`-profile legacy` ですべて無効にしてから必要なものを指定します。`-profile` は他のオプションより前に書いてください。

```bash
Tsumiki.exe -profile legacy -ec -po -1 reads_R1.fastq.gz -2 reads_R2.fastq.gz -t out
```

| オプション | 説明 | standard |
|---|---|---|
| `-profile <standard\|legacy>` | 処理の組み合わせを一括で設定 | `standard` |
| `-pp` | 前処理 | 有効 |
| `-ec` | エラー訂正 | 有効 |
| `-mk` | multi-k アセンブリ | 有効 |
| `-sr` | ペアをつないだ合成リードを次の k へ引き継ぐ | 有効 |
| `-rv` | 反復の複製前にリードでの裏付けを要求 | 有効 |
| `-la` | 未閉鎖ギャップの局所アセンブリ | 有効 |
| `-my` | 信頼 k-mer に挟まれた低頻度 k-mer の救済 | 有効 |
| `-po` | ポリッシュ | 有効 |
| `-cc` | 環状配列の接合部の検証 | 有効 |
| `-gfa` | GFA1 形式でグラフを出力 | 有効 |
| `-nc` | k 間の配列引き継ぎを無効化 | (引き継ぐ) |
| `-nt` | 低カバレッジなグラフ末端のトリミングを無効化 | (トリミングする) |
| `-mg` | 他の k の配列で未連結箇所を補う (誤アセンブリが増える可能性あり) | 無効 |
| `-cnb <spectrum\|weighted>` | コピー数推定の基準深度の求め方 | `weighted` |

### 出力ディレクトリ

| オプション | 説明 | 既定値 |
|---|---|---|
| `-rs` | 既存の出力ディレクトリにある前処理・訂正済みリードを再利用する | 無効 |
| `-rt` | 正常終了後に中間ファイルを削除する (最終結果とログは残ります) | 無効 |

## 出力

`-t` で指定したディレクトリに出力されます。

| ファイル | 内容 |
|---|---|
| `assembly.fasta` | **最終的なアセンブリ結果。通常はこれを使ってください** |
| `scaffolds.fasta` | scaffold 配列 (ポリッシュ前) |
| `contigs.fasta` | contig 配列 (scaffolding 前) |
| `unitigs.fasta` | unitig 配列 |
| `assembly.gfa` | アセンブリグラフ (GFA1)。[Bandage](https://rrwick.github.io/Bandage/) などで可視化できます |
| `assembly.report.json` | 配列統計と各種検証結果 |
| `assembly.ambiguous.tsv` | 曖昧さが残った箇所の一覧 |
| `assembly.unsupported.tsv` | リードによる裏付けが得られなかった区間の一覧 |
| `assembly.provenance.json` | 実行時の設定・入力ファイルのハッシュなどの記録 |
| `Tsumiki.log` | 実行ログ (`-log` の設定に関係なく全ログを保存) |

このほか、k ごとの途中結果 (`k31/` など) や検証用のファイルが作られます。不要であれば `-rt` で自動削除できます。

## 途中から再実行する

出力先にすでにディレクトリがある場合、結果が混ざるのを防ぐため実行を中止します。
前回の前処理・エラー訂正の結果を再利用してやり直す場合は、同じ入力とオプションに `-rs` を付けて実行します。

```bash
Tsumiki.exe -1 reads_R1.fastq.gz -2 reads_R2.fastq.gz -t out -rs
```

入力ファイルや設定が変わっている場合、該当する処理は自動的にやり直されます。
再利用されるのは前処理とエラー訂正のみで、アセンブリ本体は毎回最初から実行されます。

## ヒント

- **メモリ**: `-mem` は k-mer カウントのみの上限です。グラフ構築などで別途メモリを使うため、実際の使用量はこれより大きくなります。
- **実行時間**: multi-k は複数の k でアセンブリを繰り返すため時間がかかります。急ぐ場合は `-k 55` のように k を 1 つだけ指定してください。
- **k の選び方**: `-k` を指定する場合は、リード長より小さい値にしてください。
- **正しさの確認**: N50 が大きいことや、配列が環状と判定されたことだけでは、正しく組めた保証にはなりません。
